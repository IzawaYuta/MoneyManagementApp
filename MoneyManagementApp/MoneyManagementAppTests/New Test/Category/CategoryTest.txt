保存条件(isValid)

名前・アイコン・色がそろっていれば保存できる
名前が空、または空白のみだと保存できない
アイコン未選択だと保存できない
色未選択だと保存できない

追加(add)

追加したカテゴリーに、名前・アイコン・色が保存される
最初のカテゴリーの sortIndex は 0
追加するたびに sortIndex が末尾に増えていく(0, 1, 2)
sortIndex が飛んでいても、最大値+1 で追加される
追加したカテゴリーの ID は一意

編集(update)

名前・アイコン・色が更新される
ID と sortIndex は変わらない

削除(delete)

1件削除すると、残りの sortIndex が詰まり、順序が保たれる
複数件をまとめて削除できる
sortIndex が飛んでいても、削除後は 0 から詰め直される
全件削除して 0 件になっても削除できる
削除対象が空なら何も変わらない
存在しない ID を指定しても、他のカテゴリーに影響しない
削除後に追加すると、詰め直した sortIndex の末尾に入る
カテゴリーを削除しても、過去の収支記録(Transaction)のカテゴリー情報は残る

View 側の動作(削除対象が選択中のとき selectedCategoryID を nil に戻す処理、削除モードの切り替え、アラート表示など)。これは後で行うUIテストの対象です。
名前の前後の空白のトリム(現状の仕様ではトリムせずに保存されるため、テストしていません)
